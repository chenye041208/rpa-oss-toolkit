# rpa-oss-toolkit 使用文档

> ⚠️ 非官方工具包：本库为个人开发，并非阿里云官方出品，底层基于 `oss2` 封装。

本文档是完整使用手册；项目概览与快速入口见根目录 `README.md`。

## 1. 项目简介

rpa-oss-toolkit 是基于会话机制的阿里云 OSS 操作库，专为 RPA 流程设计：

- **会话机制**：先通过 `OSSClient.create_session()` 验证连接并创建会话，之后所有文件操作都通过 `Session` 对象执行；会话可设置有效期。
- **面向 RPA**：`Session` 实例可直接在 RPA 组件间传递，配合上下文管理器保证日志不丢失。
- **操作日志**：每次操作产生的日志先进入内存缓冲区，攒够阈值后追加写入 OSS 上的日志文件，不在本地留存日志。
- **分片传输**：超过阈值的文件自动分片上传/下载，并带指数退避重试。

## 2. 安装

```bash
pip install rpa-oss-toolkit
```

运行依赖：`oss2>=2.18.0`（Python >= 3.8）。

开发环境安装（在 `main/` 目录下）：

```bash
pip install -r requirements-dev.txt

```

## 3. 快速开始

```python
from rpa_oss_toolkit import OSSClient

session = OSSClient.create_session(
    access_key_id="your_ak",
    access_key_secret="your_sk",
    endpoint="oss-cn-shenzhen.aliyuncs.com",
    bucket="your_bucket",
    session_name="RPA流程A"
)

session.upload("local.txt", "remote/path/local.txt")
files = session.list("remote/")
url = session.get_url("remote/path/local.txt", expires=3600, attachment=True)
print(url)

session.close()
```

推荐使用上下文管理器，异常时也会自动关闭并刷新日志：

```python
with OSSClient.create_session(
    access_key_id="your_ak",
    access_key_secret="your_sk",
    endpoint="oss-cn-shenzhen.aliyuncs.com",
    bucket="your_bucket",
    session_name="RPA流程A"
) as session:
    session.upload("local.txt", "remote/path/local.txt")
```

## 4. create_session 参数详解

`OSSClient.create_session(access_key_id, access_key_secret, endpoint, bucket, session_name)`

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| access_key_id | str | 是 | 阿里云 AccessKey ID；建议使用 RAM 子账号 |
| access_key_secret | str | 是 | 阿里云 AccessKey Secret |
| endpoint | str | 是 | OSS 地域节点，如 `oss-cn-shenzhen.aliyuncs.com`（不带 `https://`） |
| bucket | str | 是 | Bucket 名称 |
| session_name | str | 是 | 会话名称，写入每条日志行用于区分来源 |

行为说明：

- 前四个参数任一为空、或 `session_name` 为空/非字符串时，抛 `ValidationError`。
- 创建 `oss2.Auth` 与 `oss2.Bucket` 后调用 `get_bucket_info()` 验证连通性；失败抛 `SessionError`（AK/SK 错误、Bucket 不存在、网络不通等）。
- 会话默认有效期取配置项 `default_expires_in`（默认 3600 秒）；到期后调用任何会校验会话的方法都会抛 `SessionError("会话已失效")`。

## 5. Session 方法详解

### 5.1 方法总表

| 方法 | 签名 | 返回 | 说明 |
|------|------|------|------|
| upload | `upload(local_path, remote_key)` | bool | 上传文件，超过阈值自动分片 |
| download | `download(remote_key, local_path)` | bool | 下载文件，自动创建本地目录，超过阈值自动分片 |
| delete | `delete(remote_key)` | bool | 删除文件，文件不存在时也返回 True |
| list | `list(prefix="")` | list[str] | 列举文件（自动翻页），返回键名列表 |
| copy | `copy(src_key, dst_key)` | bool | 同 Bucket 内复制 |
| exists | `exists(remote_key)` | bool | 判断文件是否存在 |
| get_url | `get_url(remote_key, expires=3600, attachment=True)` | str | 生成签名 URL |
| get_metadata | `get_metadata(remote_key)` | dict | 读取元数据（content_type/content_length/last_modified/etag） |
| set_metadata | `set_metadata(remote_key, metadata)` | bool | 覆盖设置元数据 |
| flush_logs | `flush_logs()` | None | 手动把缓冲区日志写入 OSS |
| get_config | `get_config(key=None)` | 值 / dict | 传 key 返回单值，否则返回全部配置副本 |
| set_config | `set_config(**kwargs)` | None | 修改配置，非法键/类型/值抛 `ConfigError` |
| close | `close()` | None | 关闭会话并刷新剩余日志 |

会话状态属性：`session_id`、`session_name`、`log_filename`、`is_valid`、`created_at`、`expires_at`。

### 5.2 文件操作

- **upload(local_path, remote_key)**：本地文件不存在抛 `UploadError`；OSS 上已存在同名 key 时也抛 `UploadError`（不覆盖）。文件大于 5 MB 时走分片上传（动态分片大小、多线程、最多重试 3 次），失败会 abort 分片任务。
- **download(remote_key, local_path)**：本地目录不存在时自动创建。文件大于 5 MB 时走分片下载，各分片写入临时目录后合并，最后清理临时文件。失败抛 `DownloadError`。
- **delete(remote_key)**：OSS 返回 404 视为删除成功；其余失败抛 `DeleteError`。
- **list(prefix="")**：使用 `list_objects_v2` 自动翻页，返回所有匹配前缀的键名。失败抛 `ListError`。
- **copy(src_key, dst_key)**：调用 `copy_object` 在同一 Bucket 内复制，失败抛 `CopyError`。
- **exists(remote_key)**：直接调用 `object_exists`。
- **get_url(remote_key, expires=3600, attachment=True)**：调用 `sign_url('GET', ...)`。`expires` 为链接有效期（秒）；`attachment=True`（默认）附加 `response-content-disposition=attachment`，生成强制下载链接，`False` 时由浏览器决定直接打开还是下载。
- **get_metadata(remote_key)**：返回 dict，含 `content_type`、`content_length`、`last_modified`、`etag`；失败抛 `OperationError`。
- **set_metadata(remote_key, metadata)**：整体覆盖文件元数据（如 `{"Content-Type": "application/pdf", "Cache-Control": "private, max-age=3600"}`），失败抛 `OperationError`。`MetadataError` 已定义但当前版本未在内部触发。

上面所有文件操作方法以及 `flush_logs()` 都会先校验会话有效性；会话已关闭或过期时抛 `SessionError`。

### 5.3 会话关闭

`close()` 先将会话标记为失效，再刷新日志器缓冲区。重复调用 `close()` 不会重复刷新。使用 `with` 语句时 `__exit__` 会自动调用 `close()`，且不抑制异常。

## 6. 配置项

配置由 `ConfigManager` 集中管理，每个配置项都有默认值、类型约束与取值校验。

| 配置项 | 默认值 | 类型 | 合法值 | 说明 |
|--------|--------|------|--------|------|
| `log_prefix` | `"logs/"` | str | 任意字符串 | 日志文件在 OSS 上的路径前缀 |
| `log_buffer_size` | `50` | int | > 0 | 日志缓冲区条数阈值，达到即自动写入 OSS |
| `min_multithread_size` | `5242880`（5 MB） | int | > 0 | 分片传输阈值（字节） |
| `part_size` | `10485760`（10 MB） | int | > 0 | 分片大小（字节） |
| `max_retry_count` | `3` | int | >= 0 | 分片传输最大重试次数 |
| `retry_delay` | `2` | int / float | >= 0 | 首次重试延迟（秒），实际按重试次数递增 |
| `default_expires_in` | `3600` | int / None | None 或 > 0 | 会话默认有效期（秒），None 表示不过期 |
| `default_cache_max_age` | `3600` | int | > 0 | 下载文件时默认缓存时间（秒），当前版本仅登记配置 |

读写方式：

```python
session.get_config()                       # 返回全部配置的副本
session.get_config("log_buffer_size")      # 读取单项
session.set_config(log_buffer_size=100)    # 修改单项
session.set_config(max_retry_count=5, retry_delay=3)  # 批量修改
```

注意：

- 不存在 `buffer_size` 这类短名，传入非法键会抛 `ConfigError`。
- `set_config` 修改 `log_prefix`、`log_buffer_size` 时会同步更新日志器；其余配置项仅更新配置存储（当前传输与缓存逻辑直接使用模块常量）。

## 7. 日志机制

```
操作产生 → 内存缓冲区 → 达到阈值(默认50条) → append_object 追加写入 OSS
```

- **日志文件**：`{log_prefix}{yyyy-mm-dd}.log`，例如 `logs/2026-04-22.log`；`log_prefix` 默认 `logs/`。
- **日志行格式**：`[yyyyMMdd-HH:MM:SS.mmm][会话名]：内容`，例如 `[20260422-10:30:00.123][RPA流程A]：操作 upload 成功`。
- **缓冲刷新**：缓冲区达到 `log_buffer_size` 条时自动写入；`flush_logs()` 可手动触发；`close()`（含 `with` 退出）会刷新剩余日志。
- **追加写入**：先 `head_object` 取当前文件长度作为 position，再 `append_object` 追加，不覆盖历史日志。
- **lock 机制**：写入前检查 `{log_prefix}lock` 是否存在，存在则读取其内容并抛 `LogError("日志文件被占用，当前占用者：...")`；写入时创建 content 为 `{session_name}|using` 的 lock，写入成功后删除。若写入过程抛错，lock 可能残留，需要人工删除该对象才能继续写日志。
- **失败处理**：创建 lock 失败、追加写入失败均抛 `LogError`。
- 析构函数中的兜底刷新不保证执行，请显式 `close()`。

## 8. 异常体系

所有自定义异常继承 `OSSError`（继承内置 `Exception`），共 13 个：

| 异常 | 父类 | 触发场景 |
|------|------|----------|
| `OSSError` | Exception | 异常基类，可一次性捕获本库全部异常 |
| `ValidationError` | OSSError | `create_session` 参数为空或 `session_name` 非法 |
| `SessionError` | OSSError | 创建会话时连接验证失败；会话失效后继续操作 |
| `SessionExpiredError` | SessionError | 预留的会话过期专用异常，当前版本未在内部触发 |
| `OperationError` | OSSError | 元数据读取/更新失败的通用异常 |
| `UploadError` | OperationError | 本地文件不存在、远端键名已存在、上传或分片上传失败 |
| `DownloadError` | OperationError | 下载或分片下载失败 |
| `DeleteError` | OperationError | 删除文件失败（404 除外） |
| `ListError` | OperationError | 列举文件失败 |
| `CopyError` | OperationError | 复制文件失败 |
| `MetadataError` | OSSError | 预留的元数据校验异常，当前版本未在内部触发 |
| `LogError` | OSSError | 日志 lock 被占用、创建 lock 失败、日志写入 OSS 失败 |
| `ConfigError` | OSSError | 配置项未知、类型错误或取值非法 |

```python
from rpa_oss_toolkit import OSSClient, OSSError, SessionError, UploadError

try:
    session = OSSClient.create_session(...)
    session.upload("a.txt", "b.txt")
except SessionError as e:
    ...
except UploadError as e:
    ...
except OSSError as e:
    ...
```

## 9. 开发与测试

在 WSL 项目根目录（若已有 `venv/` 可跳过重建）：

```bash
python3 -m venv --without-pip venv
venv/bin/python /usr/share/python-wheels/pip-*.whl/pip install pip
venv/bin/pip install -r main/requirements-dev.txt
venv/bin/pip install -e main/
```

运行测试（`main/pytest.ini` 默认用 `-m "not integration"` 排除集成测试）：

```bash
# 单元测试
cd main && ../venv/bin/python -m pytest -v

# 集成测试：先把 main/.env.example 复制为 main/.env 并填入真实凭据
cd main && ../venv/bin/python -m pytest -m integration -v
```

`main/.env` 需要 `OSS_AK_ID`、`OSS_AK_SECRET`、`OSS_ENDPOINT`、`OSS_BUCKET` 四项；凭据缺失时集成测试会整体跳过。CI（`.github/workflows/ci.yml`）在 push / PR 到 master 时只跑单元测试；集成测试需本地显式运行。

## 10. 发版流程

版本号由 git tag 经 `setuptools-scm` 推导，不在代码中硬编码。

```bash
git add -A
git commit -m "feat: xxxxx"
git tag v1.x.x
git push origin v1.x.x
```

推送 tag 后 GitHub Actions 自动执行 `.github/workflows/pypi-publish.yml`：检出代码（含 tags）→ 构建 `main/` → 用 `PYPI_API_TOKEN` 上传到 PyPI。本地构建验证可执行 `python -m build main/`。
